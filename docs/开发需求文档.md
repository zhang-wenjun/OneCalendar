# Obsidian 任务、项目与日程插件开发需求文档

版本：v0.1  
日期：2026-09-22  
状态：需求基线草案；尚未进行技术验证或编码  
项目目录名：OneCalendar；插件名称：OneCalendar；插件 ID：one-calendar

## 1. 产品定位

面向个人科研、学习及工作，提供闪念捕捉、任务管理、轻量项目管理和日历日程功能。主要项目类型为代码开发、图纸绘制、文档撰写，通常持续数周。

电脑端承担完整管理，安卓端承担快速记录、查看安排和任务提醒。核心数据以 Obsidian Markdown 笔记保存，方便直接编辑、检索和长期保留。

### 1.1 要解决的问题

| 问题 | 产品目标 |
| --- | --- |
| 任务散落，容易忘记 | 统一收集与查看，突出今日、逾期和未安排任务 |
| 日程跨设备使用不便 | 利用现有笔记同步，并在插件中展示飞书日程 |
| 忘记项目推进情况 | 在总览中显示每个项目的最新备忘，随时查看关联任务 |
| 突然出现的想法来不及细想 | 提供无需分类即可保存的闪念入口 |
| 手机上需要任务提醒 | 设置后自动写入选定日历，由日历应用提供提醒 |

### 1.2 已确认的使用环境

- 电脑：Windows，主要使用端。
- 手机：Android，以轻量操作为主。
- 笔记同步：已有 Obsidian 插件 Nutstore Sync。
- 外部日历：公司飞书账号；自建应用和管理员授权能力尚不确定。
- 当前没有需要兼容的既有任务格式，可以设计统一格式。
- 个人使用，不涉及多人任务分配与团队协作。

## 2. 决策状态与范围

本文区分三类内容：

- **已确认**：用户明确表达的需求，作为首版目标。
- **建议默认**：为便于开发补充的规则，可在界面和技术设计阶段调整。
- **待验证**：涉及平台能力、账号权限或同步行为，不能视为已经可实现。

### 2.1 首版范围（已确认）

1. 闪念快速记录与统一收集箱。
2. 任务管理，无日期或指定日期，可绑定多个项目。
3. 固定周期、完成后间隔、周一至周五重复任务。
4. 轻量项目、最新备忘、备忘历史和关联任务列表。
5. 电脑端信息总览与状态分列看板。
6. 有明确时间段的日程，以及飞书日程只读展示。
7. 手机快速记录闪念和临时任务、查看日程。
8. 在插件内设置任务提醒后自动写入日历，具体方案待验证。
9. Markdown 核心数据及与现有 Nutstore Sync 使用方式的兼容。

### 2.2 首版不纳入

- 团队协作、成员分工、审批与权限体系。
- 项目阶段层级、里程碑、甘特图、任务依赖和子任务体系。
- 完整的外部日历双向编辑、会议邀请和参会人管理。
- 自建笔记云同步服务。
- 复杂工时统计、自动排期、AI 功能。
- 自动识别法定节假日和调休。工作日重复暂按周一至周五处理。
- 强制为任务安排执行时段。

自动日历提醒属于首版目标，不能因技术困难直接以手动导出替代；若验证后无法实现，需要明确记录限制并重新确认范围。

## 3. 核心对象与关系

| 对象 | 定义 | 时间与关联规则 |
| --- | --- | --- |
| 闪念 | 尚未决定是否行动的想法 | 自动记录创建时间，可关联项目或转为任务 |
| 任务 | 需要完成的行动 | 日期可选，可关联零个、一个或多个项目 |
| 项目 | 组织相关工作的轻量容器 | 包含最新备忘、历史备忘和关联任务 |
| 项目备忘 | 一次对项目现状或下一步的记录 | 新增后替换当前展示，旧记录进入历史 |
| 本地日程 | 占用明确时间段的安排 | 开始与结束时间必填，可选关联任务 |
| 外部日程 | 从飞书读取的安排 | 标明来源，首版只读 |
| 提醒关联 | 本地任务与日历提醒之间的对应关系 | 用于创建、更新、取消和去重 |

### 3.1 基本关系

- 任务与项目为多对多关系，同一任务只保存一份。
- 在任意视图完成任务，所有关联项目和视图显示同一结果。
- 项目进展主要由最新备忘表达，不强制填进度百分比。
- 闪念关联项目不等于创建任务；归档不等于删除。
- 任务计划日期、截止日期、日程时间段和提醒时间分别表达不同含义。
- 无日期任务可以单独设置提醒时间，不因此强制增加计划日期。

## 4. 功能需求

### 4.1 闪念

**已确认：**快速记录到统一收集箱，之后再整理。

建议交互：

- 电脑提供按钮与 Obsidian 命令，手机首页提供显著入口。
- 内容为唯一必填项，不要求先填标题、日期、标签或项目。
- 保存时自动记录创建时间。
- 提供待整理、已整理、已归档视图，可搜索内容。
- 支持转为任务、关联项目、扩写为笔记和归档。
- 转为任务保留来源链接，并标记为已整理，避免重复转换。

统一收集箱是统一的操作界面，不要求所有内容存入同一个 Markdown 文件。

### 4.2 任务

**已确认：**日期可选，可以绑定多个项目；手机支持快速创建临时任务。

建议字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 稳定标识 | 自动 | 改名、移动或变更项目时不改变 |
| 标题 | 是 | 具体行动 |
| 状态 | 自动默认 | 待办、进行中、已完成、已取消 |
| 计划日期 | 否 | 希望在哪一天处理，不要求时间段 |
| 截止日期 | 否 | 最晚完成日期，与计划日期独立 |
| 关联项目 | 否 | 零到多个项目标识 |
| 正文 | 否 | 说明、清单、笔记链接或资料链接 |
| 重复规则 | 否 | 见重复任务章节 |
| 提醒时间 | 否 | 独立的日期和时间 |
| 创建、修改、完成时间 | 自动 | 用于排序、记录与同步 |

建议视图：收集箱、今日、近期、未安排、逾期、全部、已完成，以及项目内任务列表。

建议默认定义：

- 任务收集箱显示尚未分配项目且没有计划日期的未完成任务。
- 今日显示计划日期为今天或截止日期为今天的未完成任务，重复命中只显示一次。
- 逾期以截止日期判断；错过计划日期只表示未按计划处理，不自动等同于截止逾期。
- 未安排表示没有计划日期，与是否关联项目无关。
- 已完成和已取消任务不出现在默认待办列表，但可检索。

首版采用受管理目录中的统一任务格式，不承诺自动解释整个库内所有任意格式的复选框。

### 4.3 重复任务

**已确认：**支持以下三类规则。

| 规则 | 示例 | 基本语义 |
| --- | --- | --- |
| 固定周期 | 每天、每周指定星期、每月指定日期 | 按日历规则计算下一次，不因本次晚完成而整体后移 |
| 完成后间隔 | 完成后 7 天 | 从实际完成日期计算下一次 |
| 工作日 | 周一至周五 | 首版不查询节假日或调休数据 |

建议默认行为：

- 重复规则与各次执行记录分别保存，完成一次不会将整个系列永久完成。
- 每个周期实例拥有稳定标识；多设备处理不能重复生成同一个实例。
- 保留完成和跳过记录；漏做的历史默认合并展示，展开后可查看。
- 支持跳过本次、暂停重复、结束重复，并保留历史。
- 修改规则默认仅影响尚未开始的后续实例，不改写已完成记录。
- 完成后间隔任务未完成时，不持续生成下一次任务。
- 每月指定日期遇到不存在的日期，建议采用当月最后一天，并在设置界面明确提示。
- 固定周期按日历日期计算，避免使用固定毫秒数替代天数而造成时区或夏令时偏差。

重复提醒优先保持与任务实例一一对应；是否使用日历原生重复事件，取决于日历能力验证结果。

### 4.4 项目及备忘

**已确认：**项目保持简单，不设置阶段或子任务层级。

- 项目包含名称、最新备忘、备忘历史及关联任务。
- 用户每次输入一条新备忘；保存后成为最新备忘。
- 旧备忘存储但不在项目默认页面或首页反复展示。
- 用户主动打开历史后，可按时间查看旧备忘。
- 项目内可以浏览全部关联任务，并按状态筛选。

建议补充：

- 项目卡片显示名称、最新备忘、更新时间、未完成任务数。
- 支持项目归档；归档不删除任务，也不自动完成任务。
- 多项目共享任务的数量在各项目内分别统计，在全局统计中按任务标识去重。
- 两台设备同时新增备忘时保留两条记录；并列时间用稳定规则决定默认展示，并允许查看全部记录。

### 4.5 日历与日程

**已确认：**本地日程有时间段，飞书已有日程只读展示。

- 本地日程至少包含标题、开始时间、结束时间。
- 结束时间必须晚于开始时间，支持跨天。
- 首版建议提供月历和每日议程，按开始时间排序。
- 区分本地日程、飞书日程、任务日期标记，避免把任务日期误显示为占用全天的会议。
- 飞书已有日程不在插件内编辑或删除。
- 外部日程缓存可离线查看，并展示最近成功获取时间；无法刷新时保留缓存。
- 外部全天日程和重复日程应按来源语义展示，不强制套用本地日程输入限制。
- 同一条插件创建的提醒若又从飞书读回，需合并或关联展示，避免出现重复条目。

### 4.6 手机任务提醒

**已确认：**在插件内设置后自动写入日历，不以跳转到日历手动确认作为目标体验。用户接受手机系统日历或飞书，优先选择简单、可靠的方案。

能力边界：

- 现有飞书日程保持只读。
- 若采用飞书承载提醒，另行申请创建和维护插件自身提醒所需的最小能力；不扩展为任意日程双向编辑。
- 飞书账号权限、安卓日历访问方式、是否需要辅助服务均待验证。
- 手机端设置提醒为已确认需求；电脑端设置后自动到达手机属于待路线确定的扩展能力，暂不作为已确认验收项。

提醒流程：

1. 用户设置提醒时间并保存任务。
2. 本地立即保存，提醒状态显示待同步。
3. 向选定日历写入，成功后保存外部标识并显示已同步。
4. 失败时显示可理解的原因，并提供重试。
5. 修改提醒后更新原有日历记录，不另建无关记录。
6. 取消提醒或完成任务后，取消尚未触发的对应提醒；离线时进入待处理状态。

提醒状态至少包括：未设置、待同步、已同步、同步失败、待取消、已取消。

验收必须包括手机锁屏和 Obsidian 未运行时的实际通知。自动写入成功与通知实际送达分别验证，不能仅凭接口成功认定提醒功能通过。

## 5. 界面与操作

### 5.1 Windows

两种主要工作视图均为已确认需求：

- **信息总览**：今日任务、近期日程、逾期事项、项目最新备忘和闪念入口。
- **状态看板**：按待办、进行中、已完成分列，支持项目筛选。已取消默认隐藏。

其他页面：任务列表、项目详情、闪念收集箱、日历、设置。

建议支持键盘快捷操作；拖动任务可改变状态，同时提供菜单操作，避免功能只依赖拖动。首版不要求持久化自定义卡片排序。

### 5.2 Android

主要入口为快速记录、今天、收集箱。

- 快速记录可切换闪念和临时任务。
- 今天显示当天任务与日程，支持完成任务、简单编辑和设置提醒。
- 收集箱显示未整理内容。
- 项目浏览可轻量提供，不要求与电脑端相同的复杂布局。
- 触控区域适合单手操作，无需鼠标悬停；输入法弹出后仍可完成保存。

## 6. 数据与存储建议

以下为架构建议，不是已经完成的实现或最终文件格式。

### 6.1 Markdown 作为核心数据来源

- 项目、任务、闪念、本地日程和备忘历史保存为可读 Markdown。
- 属性保存于统一字段中，正文保留用户可编辑的自由内容。
- 缓存和搜索索引可以重建，不能成为核心内容唯一副本。
- 直接编辑 Markdown 后刷新视图；格式错误应定位到对应文件，不静默丢弃内容。
- 更新字段时保留不属于插件管理的正文和未知属性。

### 6.2 建议目录

```text
TaskCalendar/
  Tasks/       # 任务及重复执行记录
  Projects/    # 项目信息
  Memos/       # 项目备忘，每条独立保存
  Ideas/       # 闪念
  Events/      # 本地日程
```

统一收集箱通过索引汇总。建议每条核心对象独立成文件，降低多个设备同时修改一个大文件的概率，但这不能消除所有同步冲突。

数据格式设计阶段需明确字段名、格式版本、重复实例表示、外部映射存放位置以及迁移规则。

### 6.3 标识、关联和删除

- 每个对象具有稳定标识，关联不只依赖文件名或路径。
- 改名或移动后重新建立索引，保持项目与任务关系。
- 找不到关联对象时显示可恢复的缺失状态，避免直接删除关联。
- 首版优先提供归档，永久删除通过 Obsidian 的删除流程处理。
- 外部提醒的取消待办须在相关文件移走或删除后仍可追踪，具体存储方案在数据设计中确定。

## 7. 同步、可靠性与安全

### 7.1 两条同步链路

| 链路 | 职责 |
| --- | --- |
| Nutstore Sync | 在设备间同步受管理的 Markdown 文件 |
| 日历连接模块 | 获取飞书日程，并按最终选定方案维护任务提醒 |

不能将笔记保存成功等同于另一端已收到，不能将本地提醒保存成功等同于日历写入成功。

### 7.2 同步要求

- 本地操作不依赖网络，外部修改保存为可恢复待办。
- 监听同步引起的文件变化并刷新视图。
- 重复重试、应用重启和多设备处理应避免产生重复外部日程。
- 验证 Nutstore Sync 实际同步哪些目录和配置；不假定插件内部配置自动同步。
- 两端冲突保留可恢复内容；插件识别出的重复标识或异常文件应提示用户处理。
- 无法保证底层同步器一定保留所有冲突，因此必须以实际双端测试确认可承诺的行为。

### 7.3 授权与凭据

- 凭据不写入普通 Markdown、可分享笔记或日志。
- 是否支持设备安全存储、如何续期和撤销授权，在接入验证阶段确定。
- 发布的插件包不得包含开发者的应用密钥。
- 若接入路线需要长期运行的服务或用户自行部署，须作为架构决策明确说明，不能默认为用户已有条件。

### 7.4 性能与兼容

- 使用兼容 Obsidian 移动端的能力，不能依赖仅桌面可用的 API 完成核心流程。
- 索引以增量更新为主，避免每次输入或切换视图都扫描全库。
- 规模建议以 5,000 条任务、1,000 条闪念、100 个项目进行基准测试；具体响应时间目标待测试设备确定。
- 最低 Obsidian 与 Android 版本在验证阶段确定，不能仅以桌面模拟手机作为兼容验收。

## 8. 开发顺序与交付物

### 阶段 0：技术可行性验证

1. 确认公司飞书账号可用的读取授权方式和可访问日历。
2. 对比自动写入飞书与安卓日历的路线，验证真实手机通知。
3. 验证 Nutstore Sync 的双端文件同步、离线修改及冲突表现。
4. 确认最低版本、需要的授权和是否需要额外服务。

交付：验证结论、可用路线、限制与未解决问题。无法实现的首版目标必须明确报告。

### 阶段 1：本地管理闭环

实现数据格式、索引、闪念、任务、轻量项目和备忘历史；验证直接编辑 Markdown、改名和移动。

### 阶段 2：视图与重复任务

实现电脑总览、任务看板、重复任务、手机快速记录和轻量视图。

### 阶段 3：日历接入

实现本地日程、飞书只读展示、日历提醒及其同步状态、重试与去重。

### 阶段 4：双端验收与交付

完成 Windows 和安卓真机测试、安装说明、同步配置说明、授权说明、数据格式说明及已知限制。验证备份和恢复后再迁入真实长期数据。

## 9. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 手机记录闪念 | 只输入内容即可保存；同步后电脑可查看和整理 |
| A02 | 闪念转为任务 | 任务保留来源，闪念可查，不重复转换 |
| A03 | 多项目关联 | 同一任务关联两个项目；在一个项目中完成后，两处状态一致 |
| A04 | 更新项目备忘 | 新记录成为唯一默认展示；旧记录仍可在历史中查看 |
| A05 | 日期可选 | 无日期任务可正常创建、检索和关联项目，不被强制放进日程 |
| A06 | 总览与看板 | 可切换两种视图，状态修改一致，项目卡片显示最新备忘 |
| A07 | 重复规则 | 固定周期、完成后间隔、周一至周五均按规则产生后续实例 |
| A08 | 重复边界 | 月末、漏做、跳过、暂停与规则变更有明确结果，历史不被改写 |
| A09 | 本地日程 | 校验时间段，正确显示跨天日程，任务日期与日程可区分 |
| A10 | 飞书读取 | 授权后显示可访问日程；离线显示缓存与更新时间，不允许编辑来源日程 |
| A11 | 手机自动提醒 | 插件内设置后自动写入日历，无需手动确认日历表单；锁屏及退出 Obsidian 后实测收到通知 |
| A12 | 提醒变更 | 修改、取消、完成任务后对应更新提醒；失败状态可见且可重试 |
| A13 | 去重 | 多次重试和双端同步不为同一实例生成重复提醒或重复任务 |
| A14 | Markdown 编辑 | 手动改标题、日期或项目关联后视图更新，正文与其他属性保留 |
| A15 | 改名与移动 | 对象路径变化后关联仍可解析，缺失对象有提示 |
| A16 | 离线与冲突 | 两端离线记录可在同步后恢复；冲突测试不出现未提示的插件侧覆盖丢失 |
| A17 | 手机操作 | 输入法开启时仍可保存，主要操作不依赖拖动或悬停 |
| A18 | 授权失效 | 不影响本地记录；日历失败可理解，重新授权后可继续处理待办 |
