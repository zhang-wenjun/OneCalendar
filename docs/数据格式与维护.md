# 0.3.0 当前存储方式

任务和闪念保存在日记的普通 Markdown 列表中。任务使用复选框，闪念使用 `- #闪念 内容`；多行说明使用缩进的引用段。创建、编辑、状态变更都作用于原日记，不创建对应的 Tasks/Ideas 文件。行尾 HTML 注释保存稳定标识及附加关系，但无需专用 frontmatter。

每个项目位于 `Projects/项目名/项目名-Memo.md`。项目标题下是介绍，备忘以日期二级标题分段，最新在前，历史不拆文件。已有普通 Memo 也可纳入；原有 YAML 和笔记内容在编辑时保留。

旧的独立记录会迁移到上述位置并保留 id；迁移后的原件移入 LegacyBackup，扩展名 .bak，不再索引。Events、Series、Reminders 仍使用下文所述 YAML 记录方式。具体使用及同步范围见 README。

# 数据格式与维护

适用版本：TaskCalendar 0.1.0，数据格式版本 1。

## 文件与索引

核心记录使用 Markdown 文件，YAML 属性区描述结构，正文保存自由文本。目录默认为库内 `TaskCalendar`：

| 目录 | tc 值 | 内容 |
| --- | --- | --- |
| Tasks | task | 单次任务及重复任务实例 |
| Projects | project | 轻量项目 |
| Memos | memo | 每次新提交的项目备忘 |
| Ideas | idea | 闪念原文 |
| Events | event | 本地时间段日程 |
| Series | series | 重复规则、调度位置 |
| Reminders | reminder | 外部提醒对应关系及待办状态 |

每条记录都有 `id`、`tc`、`title`、`created` 和 `updated`。新记录另含 `format: 1` 和 `revision`。没有 format 的本版早期记录按同一格式读取；高于 1 的格式拒绝修改并显示问题，未来版本应提供明确迁移。

id 使用字母、数字、下划线或连字符。文件名由 id 生成，标题用于插件界面展示。关联以 id 为依据，不依赖文件路径。移动和改名可以保留关联；复制整篇笔记时必须为新对象分配新 id，否则作为冲突副本提示并拒绝选择其中一份更新。

启动时扫描 Markdown 建立内存索引，之后监听文件创建、修改、移动和删除事件。索引可从文件重建，无需恢复额外数据库。

## 普通任务示例

```yaml
---
tc: task
id: example-task-001
title: 完成接口说明
created: 2026-09-22T02:00:00.000Z
updated: 2026-09-22T02:00:00.000Z
format: 1
revision: 1
status: todo
projects:
  - example-project-001
  - example-project-002
plan: 2026-09-23
due: 2026-09-25
---
```

属性区之后可以写说明、链接或清单。删除可选日期属性即可恢复无日期任务。状态为 `todo`、`doing`、`done`、`cancelled`、`skipped`。

`remind` 表示独立提醒时间，例如 `2026-09-23T09:00`。本地无时区时间按当前设备时区解释，两端建议使用同一时区。`source` 记录来源闪念 id。重复实例另有 `series` 和 `occurrence`。

手动修改状态会在索引更新后反映到界面。“完成后间隔”实例手动改为 done 或 skipped、但未填写 completed 时，调度器在检测时补充完成时间并计算下一次。

## 项目和备忘

项目可使用 `archived: true` 归档，不改变关联任务状态。每条备忘的 `project` 指向项目 id，正文是完整备忘。默认取 created 最新的记录；同时间按 id 稳定排序。旧备忘不被覆盖，历史入口可以查阅。

## 重复任务

- `rule`：daily、weekly、monthly、weekdays、after。
- `interval`：正整数，daily 为天数、weekly 为周数、monthly 为月数、after 为完成后天数。weekdays 固定使用周一至周五。
- `occurrence`：规则开始或修改后生效日期。
- `next`：固定规则下一段处理位置，不建议手动修改。
- `weekdays`：weekly 对应的星期列表，0 为周日、1 为周一，以此类推。
- `monthday`：monthly 对应的日期，短月取月末。
- `reminderTime`：每次提醒的 HH:mm。
- `dueOffset`：截止日期相对计划日期的天数，可省略。
- `paused`、`ended`：是否暂停或结束继续生成。

固定周期实例标识由 series id 和日期组成。after 实例另有 sequence，使用循环序号构建标识，因此同一天提前完成多次也不会把下一次误认为同一条任务。

修改规则时，历史与已开始实例保留；未来未开始实例重新安排，不再使用的实例保留为 cancelled，并标记 superseded。暂停和结束停止后续生成，已有实例可继续处理或单独取消。

## 外部提醒

提醒映射独立于任务文件保存，id 为 `rem_` 加任务 id。重要字段：

- task：源任务 id。
- desired：需要发送的标题和时间快照。
- synced：最近成功发送的快照。
- calendarId、externalId：外部日历和日程标识。
- generation：取消后重新创建提醒时的代数。
- status、error、attempts、nextRetry：状态、错误及退避重试信息。

重试使用稳定创建标识；修改时使用 externalId 更新。首次写入前固定 calendarId，避免重试时因设置变化写入另一个日历。网络错误采用逐步延长的重试间隔，设置页可立即重试。

这些文件应与任务一起同步和备份。不要只恢复任务而遗漏映射，否则无法可靠判断外部提醒是否已经创建。

任务文件暂时消失时不自动删除远端提醒，防止将同步过程中暂缺视为删除。映射保留，设置页提供确认取消操作。

## 冲突和恢复

表单打开后保存时比较正在修改的字段以及正文。若相同字段已经变化，拒绝覆盖；未涉及的其他字段可以保留。YAML 注释、未知属性和未修改正文在字段更新时保留。

格式错误或稳定标识重复时，首页显示文件路径和问题。请比较副本、保留需要的内容后修复属性，再让 Obsidian 重新读取。不要直接清空整个数据目录。

恢复步骤：先停止两端对相同记录的编辑，备份现状，再恢复完整 TaskCalendar 文件夹；重新打开 Obsidian，检查首页的数据问题和外部提醒状态。底层同步器已覆盖且未留存的内容，插件无法凭空恢复。

## 配置与凭据

插件 data.json 只保存功能设置和可重建的飞书日程缓存。凭据仅保留于本次会话，或由用户选择保存到 Obsidian 密钥存储，不写入普通 Markdown 或插件 data.json。当前版本需手动更新到期的飞书用户访问凭据，不提供内置 OAuth 服务。

外部日程读取和提醒写入已实现适配器；公司授权、飞书通知、安卓和 Nutstore Sync 双端行为仍属于延期实测范围。

## 0.2.0 日记内联任务

日记目录和日期格式独立于 TaskCalendar 对象目录，默认继承每日笔记配置。一个日记可以包含多条任务。普通 `- [ ]` / `- [x]` 可直接使用；扩展状态使用 `[/]` 进行中、`[-]` 取消、`[>]` 跳过。

首次通过工作台修改任务后，原行尾追加 JSON 格式 HTML 注释，保存 id、非默认计划日期、关联项目、提醒及说明等属性。未指定计划日期时取日记日期；显式清空计划日期保存为 null。状态以复选框字符为准，标题以可见文本为准。仅更新目标行并保留其他文字、缩进与换行风格；并发修改目标行时拒绝覆盖。

未修改的普通复选框使用路径、标题及同名序号推导临时身份；标识写入注释后，在标题修改和笔记移动时保持稳定。不要把带相同 id 的任务行复制为另一任务，需先移除副本中的注释。
